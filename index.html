Building and training models in PyTorch, from the Healthyfi.me workout classifier to a hand-written training loop.

optimizer.zero_grad()
preds = model(xb)
loss  = criterion(preds, yb)
loss.backward()
optimizer.step()

Everything below builds toward these five lines. Repeated for every batch of every epoch, they are how a neural network trains.

Fundamentals worth having in hand

Four ideas from the mathematics of neural networks keep coming back in PyTorch. Open each one to check your answer.

A layer takes 3 neurons in and feeds 5 neurons in the next layer. What is the shape of its weight matrix?

3 × 5: one weight for every input–output pair.

Two paths in the computation graph both lead back to the same weight. How do you combine their gradients?

Add them. The chain rule sums the contribution of every path.

Sigmoid and tanh are the usual suspects behind vanishing gradients. Why?

Their derivative is close to 0 across most of the input range, so the gradient shrinks each time it is multiplied backward through a layer.

Can a neural network do regression?

Yes. Keep the output layer's activation linear.

We now have clean, scaled, split data. Time to meet the framework we will build the model in: PyTorch. One thing to get used to right away: PyTorch will not create a single weight for a layer until you state how many values come in and how many go out.

Tensors and autograd

Just enough PyTorch to proceed: two ideas every model rests on.

  • A tensor is PyTorch's array. It does the same job as a NumPy array, but it can also track how it was computed.
  • Every trainable weight in a PyTorch model is a tensor with requires_grad=True.
  • Because PyTorch records the computation graph, it can work out ∂Loss/∂W for every weight automatically. That is autograd, the mechanism that did the chain rule for you.
import torch
print(torch.__version__)

x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
y = (x ** 2).sum()
y.backward()
print(x.grad)   # dy/dx = 2x

Autograd explorer

Change the values of x, then run y.backward() to see x.grad appear.

The gradient is 2x: PyTorch did the calculus for you. Every .backward() call you write from here on is this same mechanism, just running on a much bigger graph.

Common misconception

“requires_grad=True means PyTorch trains the tensor.” It does not. It means PyTorch tracks the tensor so a gradient can be computed later, if .backward() is called. Actually updating the values still needs an optimizer.

Building layers

A single layer with nn.Linear

A layer taking our 11 features and producing 64 outputs needs a weight matrix connecting every input to every output. PyTorch needs both the input size and the output size, stated up front. Nothing is inferred automatically from the data.

import torch.nn as nn

layer = nn.Linear(in_features=11, out_features=64)
print(layer.weight.shape, layer.bias.shape)

nn.Linear shape explorer

Change the two sizes and watch the weights and bias that PyTorch creates immediately.

nn.Linear(11, 64) creates a fully-connected layer with an 11 × 64 weight matrix and a 64-length bias vector, both created at once because we gave both sizes. Every nn.Linear needs its in_features and out_features stated explicitly; a later layer never infers its input size from the one before it.

Reading the printed shape

Conceptually the matrix connects 11 inputs to 64 outputs. PyTorch prints the weight shape in (out_features, in_features) order, so expect (64, 11).

Stacking layers with nn.Sequential

model = nn.Sequential(
    nn.Linear(11, 64),
    nn.ReLU(),
    nn.Linear(64, 4)
)
print(model)

Chain checker

Layer 2 must accept exactly what layer 1 produces. Try breaking the chain.

Notice the output layer has no activation. As with the regression case in the fundamentals, raw scores (logits) come out, and whatever turns them into probabilities is folded into the loss function instead of the model. Keep that in mind; it comes back in Part 2.

Weight initialization: where training starts

Every layer needs some starting weights, and that starting point genuinely matters. Too large, and activations and gradients can blow up as they pass through layers. Too small, and they shrink toward zero: the vanishing-gradient pattern again, triggered a different way.

nn.Linear defaults to Kaiming (He) uniform initialization, with biases also drawn from a small uniform range rather than starting at zero.

The default for nn.Linear:

w ∼ Uniform[ −1√fan_in , 1√fan_in ]

A widely used alternative across many libraries and papers:

w ∼ Uniform[ −√6√(fan_in + fan_out) , √6√(fan_in + fan_out) ]

What are fan_in and fan_out?

  • fan_in is the number of inputs coming into the layer. For nn.Linear(in_features, out_features) it is in_features.
  • fan_out is the number of outputs going out of the layer: out_features.
# nn.Linear(10, 5)
fan_in  = 10   → 10 input connections per output neuron
fan_out = 5    → 5 output neurons

Initialization ranges

Each dot is one possible starting weight, drawn uniformly from the scheme's range. Change the layer size to see how the ranges respond.

Default versus Xavier in code

layer = nn.Linear(11, 64)
print("Default (Kaiming) weight sample:", layer.weight.data.flatten()[:5])
print("Default bias sample:            ", layer.bias.data.flatten()[:5])

To get Glorot/Xavier behaviour instead, override it explicitly:

nn.init.xavier_uniform_(layer.weight)
nn.init.zeros_(layer.bias)
print("Xavier-overridden weight sample:", layer.weight.data.flatten()[:5])
print("Zero bias sample:               ", layer.bias.data.flatten()[:5])

In PyTorch, initialization is always a separate, explicit step applied to a layer that already exists. That is deliberate: how the layer is shaped and how it is initialized stay two independent decisions.

Loss function and optimizer

Two more pieces are needed before anything trains. The loss function measures how wrong the predictions are. The optimizer uses that measurement to move the weights in a better direction. In PyTorch they are two plain objects, with nothing hidden inside a single combined call.

criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

nn.CrossEntropyLoss expects two specific things:

  • Raw, un-normalized logits from the model, not softmax probabilities.
  • Integer class labels (0, 1, 2, 3), not one-hot vectors.

That is why the model deliberately has no Softmax layer. It is a requirement, not an oversight, and Part 2 returns to it.

From logits to loss

Illustrative numbers. Drag the four logits and pick the true class; the loss function handles the conversion to probabilities internally.

Writing the training loop

For each batch, the weights update only after a fixed sequence of steps. The order is the whole point.

The sequence is: reset gradients → forward pass → compute loss → compute gradients (backward) → update weights. A frequent slip is to think of “reset gradients” as the end of a step; in the code it runs at the start of the next one. zero_grad() has to run before backward(), not after step().

One batch, step by step

Move through the five lines that make up a single weight update.


      

    

    
    
    
    
  
    

  
    What zero_grad() actually does
    
  
    PyTorch accumulates gradients by default. Every .backward() call adds the new gradients to whatever is already stored in each parameter's .grad, rather than replacing them. That is useful in some advanced cases, but in a standard training loop it is not what you want: without clearing, each batch's update is contaminated by the gradients of all previous batches. optimizer.zero_grad() resets every .grad to zero, so the next backward() reflects only the current batch.
    

  
    
    
    Gradient accumulation
    Toy gradients for a single weight, one per batch. Compare the stored .grad with and without zero_grad().
    
    
    
    
    
    
    
  
    

  
    Batching with DataLoader
    
  
    Training almost never uses the whole dataset at once. The model sees small batches, and in PyTorch you build them yourself with DataLoader.
    

    from torch.utils.data import TensorDataset, DataLoader

X_train_t = torch.tensor(X_train, dtype=torch.float32)
y_train_t = torch.tensor(y_train.values, dtype=torch.long)
X_val_t = torch.tensor(X_val, dtype=torch.float32)
y_val_t = torch.tensor(y_val.values, dtype=torch.long)

train_ds = TensorDataset(X_train_t, y_train_t)
train_loader = DataLoader(train_ds, batch_size=256, shuffle=True)
    

  
    The loop itself
    
  
    This is the block of code that actually trains the model, epoch by epoch and batch by batch.
    

    def seed_everything(seed=42):
    np.random.seed(seed)
    torch.manual_seed(seed)

seed_everything()

model = nn.Sequential(
    nn.Linear(11, 32),
    nn.ReLU(),
    nn.Linear(32, 16),
    nn.ReLU(),
    nn.Linear(16, 4)
)
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

n_epochs = 500
history = {"train_loss": [], "val_loss": [], "train_acc": [], "val_acc": []}

for epoch in range(n_epochs):
    model.train()
    for xb, yb in train_loader:
        optimizer.zero_grad()
        preds = model(xb)
        loss = criterion(preds, yb)
        loss.backward()
        optimizer.step()

    # end-of-epoch bookkeeping — this is where "history" comes from
    model.eval()
    with torch.no_grad():
        train_preds = model(X_train_t)
        train_loss = criterion(train_preds, y_train_t).item()
        train_acc = (train_preds.argmax(1) == y_train_t).float().mean().item()

        val_preds = model(X_val_t)
        val_loss = criterion(val_preds, y_val_t).item()
        val_acc = (val_preds.argmax(1) == y_val_t).float().mean().item()

    history["train_loss"].append(train_loss)
    history["val_loss"].append(val_loss)
    history["train_acc"].append(train_acc)
    history["val_acc"].append(val_acc)

    if epoch % 50 == 0:
        print(f"Epoch {epoch:03d} - loss: {train_loss:.4f} - acc: {train_acc:.4f} "
              f"- val_loss: {val_loss:.4f} - val_acc: {val_acc:.4f}")
    

  
    
    
    Every epoch (500 of them)
      
    Every batch from train_loader (batches of 256, shuffled)
        
    zero_grad → forward → loss → backward → step
    
      
    End of the epochSwitch to model.eval(), measure loss and accuracy on the training and validation sets without tracking gradients, and append the four numbers to history.
    
    
    
  
    

  
    Line by line, the five-line block does this:
    
  
      
    
    • optimizer.zero_grad() clears leftover gradients from the previous batch.
      • 
    
    • model(xb) is the forward pass, producing predictions.
      • 
    
    • criterion(preds, yb) measures how wrong those predictions are.
      • 
    
    • loss.backward() has autograd compute every ∂Loss/∂W, the same mechanism as the tiny tensor example.
      • 
    
    • optimizer.step() performs the weight update. This is the moment the model learns.
      • 
  
    
  
    That block, repeated per batch and per epoch, is how a neural network trains. Nothing else is happening underneath.
    

  
    Spot the bug
    
  
    The goal here is to internalize why each step exists by seeing what breaks without one. This loop is missing a line. Predict what goes wrong before opening the diagnosis.
    

    # Broken loop — find the bug before running this
for epoch in range(n_epochs):
    for xb, yb in train_loader:
        preds = model(xb)
        loss = criterion(preds, yb)
        loss.backward()
        optimizer.step()
    
  
    What is missing, and what happens to training?
    
    optimizer.zero_grad() is missing. Gradients accumulate across every batch instead of resetting, so parameter updates keep growing rather than reflecting only the current batch. Training tends to destabilize rather than fail with a clean error.
    

  
    

    



    
  
    Reading history: loss and accuracy curves
    
  
    The history dictionary, filled by hand epoch by epoch, is the record of how training went. Plotting it takes a few lines.
    

    epochs_range = range(n_epochs)

plt.figure()
plt.plot(epochs_range, history["train_loss"], label="train")
plt.plot(epochs_range, history["val_loss"], label="val")
plt.legend()
plt.title("Loss vs Epochs")
plt.show()

plt.figure()
plt.plot(epochs_range, history["train_acc"], label="train")
plt.plot(epochs_range, history["val_acc"], label="validation")
plt.legend()
plt.title("Accuracy vs Epochs")
plt.show()
    
  
    Training loss keeps dropping, but validation loss bottoms out and starts climbing after roughly 120 epochs. The model is starting to memorize the training set instead of generalizing. That is the value of tracking both curves throughout training, not just training loss alone.

    Recap
    
  
      
    
    • nn.Linear and nn.Sequential build a model layer by layer, with every shape stated explicitly.
      • 
    
    • Weight initialization sets exactly where training starts. Kaiming is PyTorch's default; Xavier/Glorot is a common alternative.
      • 
    
    • The loss function and optimizer are two separate, explicit objects. Nothing hides behind a single setup call.
      • 
    
    • Training is a loop you write and fully control: zero_grad → forward → loss → backward → step, repeated per batch, per epoch.
      • 
    
    • Tracking history is just choosing what to record each epoch, in a plain dictionary.
      •
